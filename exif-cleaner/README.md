# 사진 위치정보 지우개

사진에 남은 촬영 위치(GPS), 촬영 일시, 기기 정보를 지우는 브라우저 도구. 파일은 기기 밖으로 나가지 않는다. 서버도 빌드도 없이 `index.html`을 열면 끝난다.

## 왜 만들었나

스마트폰 사진에는 찍은 좌표가 같이 저장된다. 블로그나 중고거래에 집에서 찍은 사진을 올리면 집 위치가 같이 올라간다. 네이버·인스타그램은 업로드할 때 이 정보를 지우지만, 카카오톡 원본 전송이나 이메일 첨부, 파일 공유는 그대로 남는다.

## 쓰는 법

폰·PC 모두 https://sejongkim-ctrl.github.io/oneday-tools/exif-cleaner/ 로 연다. PC에서는 `index.html`을 더블클릭해도 된다.

저장 방식은 기기에 따라 다르다. 폰(pointer: coarse)은 공유 시트를 띄워 "이미지 저장"으로 사진첩에 넣거나 당근·카톡으로 바로 보낸다. 파일로 내려받으면 아이폰은 사진첩이 아닌 '파일' 앱에 들어가 올릴 때 고를 수 없기 때문이다. 공유가 막히면 내려받기로 대체한다. PC는 내려받기, 두 장 이상은 ZIP이다.

## 구조

| 파일 | 책임 |
|---|---|
| `src/exif.js` | JPEG 구간·PNG 청크를 훑어 GPS·촬영일시·기기·회전 정보를 읽는다 |
| `src/strip.js` | 메타데이터 바이트만 들어내고, 회전 정보가 있으면 픽셀에 구워 넣는다 |
| `src/app.js` | 파일 입력, 전후 비교 표시, 내려받기 |
| `src/save.js` | 폰은 공유 시트, PC는 내려받기·ZIP으로 결과를 남긴다 |
| `src/zip.js` | 여러 장을 ZIP 하나로 묶는다(압축 없는 store 방식, 외부 라이브러리 없음) |
| `src/page.html`, `src/style.css` | 화면 뼈대와 스타일 |
| `build.mjs` | 위 파일을 `index.html` 한 장으로 합친다 |

소스를 고쳤으면 `node build.mjs`를 돌려 `index.html`을 다시 만든다. 브라우저는 file:// 로 열린 페이지에서 외부 JS 모듈을 CORS로 막기 때문에, 배포본은 반드시 한 파일이어야 한다.

## 형식별 처리 방식

| 형식 | 방식 | 재압축 |
|---|---|---|
| JPEG | Exif(APP1)·IPTC(APP13)·주석(COM) 구간을 잘라낸다 | 없음 |
| PNG | tEXt·zTXt·iTXt·eXIf·tIME 청크를 뺀다 | 없음 |
| HEIC | meta 박스의 iinf·iloc를 읽어 Exif·XMP 항목 위치를 찾고, 그 구간만 0으로 덮는다. 길이를 유지해 뒤쪽 위치표가 어긋나지 않게 한다 | 없음 |
| HEIC(위치표를 못 읽는 경우) | 브라우저가 열 수 있으면 다시 그려 JPG로 내보낸다. 못 열면 변환 방법을 안내한다 | 있음 |

브라우저는 HEIC를 대부분 열지 못한다(Chrome 기준). 그래서 디코딩 없이 바이트만 덮는 방식을 1순위로 쓴다. Chrome에서도 아이폰 사진을 그대로 처리할 수 있다.

## 화질을 지키는 방식

JPEG는 다시 압축하지 않는다. Exif(APP1), Photoshop IPTC(APP13), 주석(COM) 구간만 잘라내고 픽셀 데이터는 원본 그대로 옮긴다. 색 프로파일(ICC)은 남긴다. 지우면 색이 틀어지기 때문이다.

예외는 회전 정보가 있는 사진이다. 회전 값까지 지우면 사진이 눕거나 뒤집혀 보인다. 이 경우에만 회전을 픽셀에 적용해 다시 저장한다(품질 0.95).

## 검증

GPS 좌표와 회전 값이 든 JPEG, 텍스트가 든 PNG를 만들어 헤드리스 브라우저로 처리한 뒤 결과 파일을 다시 열어 확인했다.

| 입력 | 결과 |
|---|---|
| GPS·기기 정보 JPEG | Exif 태그 6개 → 0개, GPS 제거, 픽셀 차이 0 |
| 회전 값 6인 JPEG | 보이는 방향과 결과가 일치(300x400), 최대 픽셀 차이 10(재압축) |
| 텍스트 청크 PNG | 텍스트 제거, 픽셀 차이 0 |
| GPS가 든 HEIC | Exif·XMP 항목 제거, 파일 크기 동일, 바뀐 바이트는 메타데이터 구간 508바이트뿐, 그림 데이터 무변경, 픽셀 차이 0, macOS 디코더로 정상 인식 |

화면은 더블클릭과 같은 조건(file://)에서 드래그 앤 드롭, 파일 선택, 내려받기, 처음부터, 모바일 폭까지 확인했다.

여러 장을 연달아 내려받으면 Chrome이 11장째부터 조용히 막는다(12장 중 10장만 저장됨을 실측). 그래서 두 장 이상이면 ZIP 하나로 묶는다. 3.2MB짜리 12장(39MB)을 0.7초에 처리했고 그동안 화면도 멈추지 않았다.

## 사진이 밖으로 나가지 않는다는 근거

말로만 약속하지 않고 브라우저가 강제하게 만들었다.

| 장치 | 내용 |
|---|---|
| CSP `connect-src 'none'` | fetch·XHR·beacon이 전부 차단된다. 코드가 보내려 해도 브라우저가 막는다 |
| CSP `default-src 'none'` | 외부 스크립트·글꼴·이미지를 불러올 수 없다. 분석 도구나 광고가 끼어들 여지가 없다 |
| 외부 리소스 0개 | 배포본은 HTML 한 장이다. CDN도 폰트도 없다 |
| 저장소 미사용 | 쿠키·localStorage·sessionStorage·서비스워커를 쓰지 않는다 |
| 입력값 이스케이프 | 파일명과 Exif 문자열을 그대로 DOM에 넣지 않는다. 조작된 파일로 스크립트를 실행할 수 없다 |

화면 안의 "지금 외부 전송 시도해보기" 버튼이 실제로 `fetch`를 실행하고 차단 결과를 보여준다. 사용자가 직접 확인할 수 있게 한 장치다.

검증 결과(헤드리스 브라우저):

| 시험 | 결과 |
|---|---|
| 파일명에 `<img onerror=...>`를 넣은 사진 | 실행되지 않고 글자로 표시 |
| Exif 기기명에 `<script>`를 넣은 사진 | 실행되지 않고 글자로 표시 |
| 외부 전송 시도 | CSP로 차단 |
| 사진 처리 중 네트워크 요청 | 없음(썸네일용 blob 주소만 사용) |
| localStorage·sessionStorage·쿠키·서비스워커 | 전부 비어 있음 |

폰 조건은 헤드리스 브라우저의 기기 흉내(Pixel 7·iPhone 14)로 공유 시트를 가짜로 끼워 확인했다. 한 장·여러 장 공유, 공유 창 닫기, 공유 거부 시 내려받기 대체, 가로 스크롤 없음, PC 내려받기·ZIP 회귀까지 19개 항목이 통과했다. 실제 공유 시트와 사진첩 선택은 실기기에서만 확인할 수 있다.

## 한계

아이폰 사파리는 사진첩에서 고른 사진을 페이지에 넘길 때 GPS를 먼저 빼는 것으로 알려져 있다(WebKit 버그 257534). 이 경우 도구는 "위치정보 없음"으로 표시한다. 결과가 틀린 것은 아니다. 실기기 확인이 필요하다.


HEIC 중에서도 메타데이터가 idat 박스에 들어간 파일은 바이트로 지우지 못한다. 이때는 브라우저가 HEIC를 열 수 있어야 JPG 변환으로 처리된다. 동영상은 대상이 아니다.
